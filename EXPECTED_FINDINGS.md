- **SAST-01** — $db->query() on a string literal concatenated with a LIKE pattern built from $_GET['q'].
- **SAST-02** — shell_exec on a literal concatenated with the unvalidated ?format= value.
- **SAST-03** — eval() on the posted settings bundle.
- **SAST-04** — file_get_contents on a literal directory concatenated with ?name=. The plan's $dir prefix became a string literal because the rule needs one.
- **SEC-01** — Download-link JWT signing key hardcoded in the config array and passed to JWT::encode in src/token.php.
- **SEC-02** — RSA private key generated with openssl.
- **SEC-03** — Deploy token in a workflow env block. Deliberately not a provider-prefixed token (ghp_ etc.), to stay clear of GitHub push protection.
- **SEC-05** — SMTP relay token in a file that is added and then deleted two commits later. Only a git-history scan finds it. Built by scripts/seed_history.py, which derives the value from a seed so it never appears at HEAD.
- **SEC-06** — Slack incoming webhook in an ops runbook (a non-code location).

- **DEP-04** — 1 OSV record reported by osv-scanner 1.9.2, identical to the osv.dev query for this version on 2026-10-04. Renders Markdown in the preview.
- **SAFE-01** — PDO prepared statement with a bound parameter.
- **SAFE-02** — shell_exec on a command whose only variable part went through escapeshellarg. The command is bound to a variable first: see the repo-level note on arve.php.command-injection.
- **SAFE-03** — file_get_contents on basename() of the request name, after an extension allowlist. The path is bound to a variable first: see the repo-level note on arve.php.path-traversal.
- CodeQL does not support PHP, so engine_expectations.codeql is "skipped" and no entry expects it. ARVE must finish the scan as COMPLETED with CodeQL skipped: not PARTIAL, not FAILED.
- SEC-04 is deliberately unused. IDs are aligned with the Python and JS testbeds, where SEC-05 is the history-only secret and SEC-06 the runbook webhook; the PHP matrix has one HEAD secret fewer.
- Known ARVE false positive (Semgrep): arve.php.command-injection and arve.php.path-traversal match the syntactic shape f("..." . $X) for any $X, so shell_exec("cmd " . escapeshellarg($x)) and file_get_contents("dir/" . basename($x)) are reported. SAFE-02 and SAFE-03 bind the argument to a variable first; no control asserts the false positive.
- ARVE rulepack gap (PHP): the same rules need a string literal as the left operand of a single concatenation. A three-part concatenation ("a" . $x . "b"), a constant or __DIR__ prefix, or a command built in a variable is not matched. The SAST plants use the exact two-operand shape.
- composer.lock was generated with `composer update --no-install --no-security-blocking`: Composer 2.9+ refuses to resolve versions with known advisories by default. Transitive packages resolve to current, advisory-free versions.
